# Methodology

## Problem Framing

Used-car selling price prediction is framed as a **supervised regression
problem**: given a labeled dataset of past sales (features → known
`selling_price`), learn a function that maps a new car's features to an
estimated price.

## Pipeline

1. **Data Loading & Validation** (`src/data_loader.py`) — loads the raw CSV
   and fails fast with a readable error if expected columns are missing.
2. **Data Cleaning** (`src/preprocessing.py::clean_raw_data`) — deterministic,
   leakage-free transforms applied before the split: duplicate removal,
   unit-stripping (`"1248 CC"` → `1248.0`), dropping rows with an invalid
   target, dropping the unusable `torque` free-text column, basic sanity
   filters on `km_driven`/`year`.
3. **Feature Engineering** (`src/feature_engineering.py`) — `car_age`,
   `brand` extraction, rare-brand grouping into `"Other"`.
4. **Train/Test Split** (`src/train.py::prepare_data`) — 80/20, fixed
   `random_state=42`, split BEFORE any statistic-learning preprocessing
   step to prevent leakage.
5. **Preprocessing Pipeline** (`src/preprocessing.py::build_preprocessing_pipeline`)
   — median imputation + standard scaling for numeric features,
   most-frequent imputation + one-hot encoding for categorical features,
   composed with `ColumnTransformer`. Fit **only** on the training split.
6. **Model Comparison** — five baseline regressors (plus XGBoost) evaluated
   with 5-fold cross-validation on the training split only.
7. **Hyperparameter Tuning** — `RandomizedSearchCV` (20 iterations, 5-fold
   CV, bounded search space) applied to the two strongest tree-based
   candidates.
8. **Final Evaluation** — every candidate (baseline + tuned) is scored
   exactly once on the held-out test set; the model with the lowest test
   RMSE is selected as final — an objective, data-driven choice, not an
   assumption made in advance.
9. **Serialization** — the final fitted `Pipeline` (preprocessing + model)
   is saved with `joblib` to `models/used_car_price_model.pkl`.
10. **Deployment** — the Streamlit app loads the saved pipeline and serves
    predictions without retraining.

## Training / Validation / Test Set Definitions

- **Training set (80%):** used to fit preprocessing statistics and model
  parameters, and as the pool for 5-fold cross-validation.
- **Validation (via 5-fold cross-validation on the training set):** each
  fold's held-out portion estimates generalization performance during model
  *selection and tuning*, without ever touching the test set.
- **Test set (20%, held out from the start):** used exactly once, at the
  very end, to report final, unbiased performance for the already-selected
  and already-tuned model. It is never used to choose between models or
  hyperparameters.

## Avoiding Data Leakage

- The train/test split happens before any statistic (imputation medians,
  one-hot categories, feature scaling) is learned.
- `ColumnTransformer` is fit only via `Pipeline.fit(X_train, y_train)`;
  `X_test` only ever goes through `.transform()` (previously-learned
  statistics), both inside `cross_validate`/`RandomizedSearchCV` (which
  internally re-fit per fold on the training portion of that fold) and in
  the final test-set evaluation.
- Cleaning steps applied before the split (duplicate removal, unit
  stripping, sanity filters) are deterministic row/string transforms that
  do not learn any statistic from the data, so applying them before the
  split does not leak test-set information.

## Reproducibility

- `RANDOM_STATE = 42` fixed in `src/config.py`, used consistently for the
  train/test split, cross-validation folds, `RandomizedSearchCV`, and every
  model with a random component.
- All reported metrics are generated by running `python -m src.train`
  against the unmodified dataset in `data/raw/used_cars.csv` — re-running
  the same command on the same file reproduces the same numbers exactly.
- Package versions used during development are pinned in `requirements.txt`.
